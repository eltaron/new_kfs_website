# خدمة «طلب صلاحية الموقع» — الروابط وطريقة الدخول

> ملخص سريع للدخول على الخدمة ولوحة التحكم. الشرح الكامل (سير العمل، الحالات، الإشعارات، القسم التقني) في [`site-validity-service.md`](site-validity-service.md).
> الوحدة: `modules/SiteValidity` — آخر تحديث: 2026-10-12

## 1. ما هي الخدمة؟

خدمة إلكترونية يقدّم من خلالها المواطن طلب **صلاحية موقع** (لترخيص بناء، توصيل مرافق، ملف تصالح، أو مشروع استثماري) ويتابعه أونلاين:

تقديم الطلب ← المركز الجيومكاني يحدد موعد المعاينة ← مهندس التنظيم يوافق ← المعاينة الميدانية ← رفع المرفقات الفنية ← قرار المهندس (استيفاء أو انتهاء) ← المواطن ينزّل الملف النهائي.

| نوع الخدمة | الرسوم الافتراضية |
|---|---|
| صلاحية موقع لترخيص بناء | 500 ج.م |
| صلاحية موقع لتوصيل المرافق | 300 ج.م |
| صلاحية موقع لملف تصالح | 750 ج.م |
| صلاحية موقع لمشروع استثماري | 1500 ج.م |

(الرسوم وأنواع الخدمة قابلة للتعديل من لوحة التحكم ← «إعدادات الخدمة».)

## 2. الروابط

على جهاز التطوير المحلي الموقع يعمل على **`http://127.0.0.1:7500`** (المنفذ 8000 مشروع آخر). على السيرفر استبدل البداية بدومين البوابة.

| الصفحة | الرابط المحلي |
|---|---|
| **لوحة التحكم (الموظفين)** | http://127.0.0.1:7500/site-validity |
| **تسجيل دخول لوحة التحكم** | http://127.0.0.1:7500/site-validity/login |
| صفحة الخدمة للمواطن (عامة) | http://127.0.0.1:7500/site-validity-request |
| تقديم طلب جديد (يتطلب دخول) | http://127.0.0.1:7500/site-validity-request/apply |
| طلباتي | http://127.0.0.1:7500/site-validity-request/my-requests |

## 3. الدخول على لوحة التحكم

1. افتح `/site-validity/login`.
2. أدخل **البريد الإلكتروني** وكلمة المرور.
3. إن كانت المصادقة الثنائية مفعّلة على حسابك أدخل الكود من تطبيق Google Authenticator.
   (إجبار كل الموظفين على تفعيلها يتحكم فيه `TWO_FACTOR_REQUIRE_FOR_STAFF` في `.env` — مغلق افتراضياً.)
4. ستظهر لوحة التحكم: إحصائيات الطلبات، المواعيد القادمة والمتأخرة، ومن القائمة الجانبية «الطلبات» و«إعدادات الخدمة».

### من يقدر يدخل اللوحة؟

أي حساب حالته غير موقوفة/مرفوضة وله أحد الأدوار التالية:

| الدور (اسم تقني) | الوصف | الصلاحيات |
|---|---|---|
| `site_validity_admin` | مسؤول الخدمة | كل شيء + الإعدادات + إدارة حسابات الموظفين |
| `geo_center` | المركز الجيومكاني | تحديد موعد المعاينة، «تمت المعاينة»، رفع المرفقات الفنية |
| `planning_engineer` | مهندس التنظيم | الموافقة/الرفض، استمارة المعاينة، طلب الاستيفاء، إنهاء الطلب ورفع الملف النهائي |
| `tech_center` | المركز التكنولوجي | **إضافة طلب جديد فقط** نيابةً عن المواطن («الطلبات» ← «إضافة طلب جديد»)، ويرى الطلبات التي أدخلها فقط بلا أي إجراءات. يُربط الطلب بحساب المواطن إن وُجد بنفس الرقم القومي، وإلا يُسجل باسم المركز |
| `super_admin` | مدير النظام | يدخل كل اللوحات ويُعامل كمسؤول الخدمة |

- حسابات `super_admin` الموجودة في بيانات الموقع تقدر تدخل مباشرة ببريدها وكلمة مرورها.
- لإضافة موظف جديد: ادخل كمسؤول الخدمة ← «حسابات المستخدمين» ← إنشاء، واختر الدور.

### الدخول كمواطن

من صفحة الخدمة اضغط «تقديم طلب جديد» ← سجّل الدخول **بالرقم القومي وكلمة المرور** (أو أنشئ حساباً) ← يرجعك النظام للنموذج.

## 4. الحسابات التجريبية

تُنشأ بالأمر التالي (آمن وقابل لإعادة التشغيل، لا يمسح بيانات موجودة):

```bash
php artisan db:seed --class="Modules\SiteValidity\database\seeders\SiteValidityDemoSeeder"
```

كلمة المرور: قيمة `DEMO_PASSWORD` في `.env` إن وُجدت، وإلا **`SvDemo@2026#Kfs`**

| الحساب | البريد (للوحة) | الرقم القومي (لبوابة المواطن) | الدور |
|---|---|---|---|
| مسؤول الخدمة | `sv.admin@demo.kfs.invalid` | 28503151500231 | site_validity_admin |
| المركز الجيومكاني | `sv.geo@demo.kfs.invalid` | 28807221500342 | geo_center |
| مهندس التنظيم | `sv.engineer@demo.kfs.invalid` | 28611041500153 | planning_engineer |
| المركز التكنولوجي | `sv.tech@demo.kfs.invalid` | 28901011500457 | tech_center |
| مواطن 1 | `sv.citizen1@demo.kfs.invalid` | 29004121500575 | مواطن |
| مواطن 2 | `sv.citizen2@demo.kfs.invalid` | 29309051500686 | مواطن |

> إن كان الرقم القومي مستخدماً لحساب آخر يولّد الـ seeder رقماً بديلاً — الرقم الفعلي مكتوب في `storage/app/private/demo-accounts.txt`.
> هذه الحسابات للتجربة فقط — لا تشغّل الـ seeder على السيرفر الفعلي.

## 5. التشغيل لأول مرة على قاعدة بيانات جديدة

جداول الخدمة (`sv_*`) تُنشأ من migration الوحدة، فبعد استيراد قاعدة بيانات قديمة لازم:

```bash
php artisan migrate        # ينشئ جداول sv_* وباقي الجداول الناقصة
php artisan db:seed --class="Modules\SiteValidity\database\seeders\SiteValidityDemoSeeder"   # اختياري: أدوار + إعدادات + حسابات تجريبية
php artisan optimize:clear
```

بدون الـ migration صفحة `/site-validity` هتطلع خطأ «Table 'sv_…' doesn't exist».

## 6. مشاكل شائعة

| المشكلة | الحل |
|---|---|
| «These credentials do not match» في اللوحة | اللوحة تدخل **بالبريد** وليس الرقم القومي. |
| يدخل ثم يظهر 403 | الحساب ليس له دور من الأدوار في الجدول أعلاه، أو حالته `rejected`/`inactive`. |
| يطلب إعداد المصادقة الثنائية | `TWO_FACTOR_REQUIRE_FOR_STAFF=true` — فعّلها من القائمة ← «المصادقة الثنائية». |
| تعديل الإعدادات لا يظهر | الإعدادات مخزنة مؤقتاً 5 دقائق؛ نفّذ `php artisan cache:clear`. |
